# تشغيل EmergencyPlus على الدومين (https://eplus.life) مع بقاء البيانات في العيادة

## الفكرة باختصار

```
 داخل العيادة (Wi-Fi / كيبل)                      خارج العيادة
 ───────────────────────────                      ─────────────────────────
 http://192.168.x.x:4080  ── كما الآن ──┐          جهاز عليه تطبيق Tailscale
 https://eplus.life       ──────────────┤          https://eplus.life
                                        ▼                 │ (نفق VPN مشفّر من طرف لطرف)
                         ┌──────── جهاز السيرفر في العيادة ─┴──────────┐
                         │  Caddy :443  (HTTPS للدومين)                │
                         │     └─► البرنامج :4080 ─► قاعدة البيانات      │
                         │  الملفات والنسخ الاحتياطية — كلها هنا فقط     │
                         └─────────────────────────────────────────────┘
```

- **قاعدة البيانات والملفات لا تخرج من جهاز العيادة**، ولا يتم نسخها أو نقلها لأي مكان.
- **لا يُفتح أي منفذ على راوتر العيادة.** من الإنترنت العام لا يمكن الوصول للبرنامج إطلاقاً.
- **الدخول بعنوان IP** (`http://192.168.x.x:4080`) يبقى كما هو داخل العيادة.
- **الدومين** يعمل بـ HTTPS بشهادة رسمية من Let's Encrypt:
  - داخل العيادة؛
  - ومن خارجها على الأجهزة المسجّلة في Tailscale فقط.

### لماذا هذا الحل؟

| الخيار | لماذا لم يُعتمد / اعتُمد |
|---|---|
| **Cloudflare Tunnel** | ❌ الاتصال المشفّر يُفك عند خوادم Cloudflare، أي أن بيانات المرضى تمر مكشوفة عبر شركة خارجية. هذا يخالف شرط عدم إرسال البيانات لخدمة خارجية. |
| **فتح منفذ 443 على الراوتر** | ❌ يعرّض صفحة الدخول لكل الإنترنت (محاولات اختراق وتخمين كلمات سر). وغالباً لا يعمل أصلاً لأن مزودي الإنترنت في الأردن يستخدمون CGNAT بدون IP عام حقيقي. |
| **VPN عبر Tailscale (المعتمد)** | ✅ تشفير WireGuard من الجهاز إلى سيرفر العيادة مباشرة، ولا تستطيع Tailscale قراءة البيانات. لا يصل للبرنامج إلا الأجهزة التي تسجّلها أنت. لا منافذ مفتوحة، ويعمل بدون IP ثابت. |

**أين يُستخدم Cloudflare؟** لإدارة سجلات DNS للدومين فقط، بوضع «DNS only» (الغيمة رمادية). Cloudflare لا يمرّ عبره أي اتصال بالبرنامج. الـ API Token يُستخدم فقط لإثبات ملكية الدومين عند إصدار شهادة HTTPS وتجديدها، عبر سجل TXT مؤقت.

| البند | من ينفّذه |
|---|---|
| ملفات الإعداد والسكربتات وتعديلات الكود (HTTPS، الكوكيز، الأمان) | ✅ منفّذ في المشروع |

## خطوات التنفيذ بالترتيب

### 1) تثبيت عنوان السيرفر داخل العيادة
- في إعدادات الراوتر ← DHCP Reservation، احجز عنواناً ثابتاً لجهاز السيرفر، مثلاً `192.168.1.93`.
- تأكد من العنوان على السيرفر بالأمر `ipconfig`، وابحث عن IPv4 Address الذي يبدأ بـ 192.168.
- ⚠️ **لا تفعّل Port Forwarding لأي منفذ** على الراوتر.

### 2) إدارة DNS للدومين عبر Cloudflare (مجاني)
1. أنشئ حساباً على cloudflare.com ← **Add a site** ← اكتب `eplus.life` ← اختر الخطة **Free**.
2. سيعطيك Cloudflare عنواني Nameservers. ادخل حسابك لدى الشركة التي اشتريت منها الدومين ← إعدادات الدومين ← **Nameservers**، واستبدلهما بعنواني Cloudflare.
3. انتظر حتى يظهر الدومين **Active** في Cloudflare. يستغرق ذلك من دقائق إلى عدة ساعات.
4. أنشئ الـ API Token:
   - **My Profile ← API Tokens ← Create Token ← قالب "Edit zone DNS"**.
   - في **Zone Resources** اختر: `Include → Specific zone → eplus.life`.
   - **Create** ← انسخ الرمز واحفظه، فهو يُعرض مرة واحدة فقط.

### 3) تثبيت Tailscale على جهاز السيرفر
1. حمّل Tailscale for Windows من tailscale.com/download وثبّته، ثم سجّل الدخول.
2. اعرف عنوان السيرفر في Tailscale من موجّه الأوامر بالأمر `tailscale ip -4`، وستحصل على عنوان مثل `100.101.102.103`.
3. من لوحة التحكم login.tailscale.com ← **Machines** ← جهاز السيرفر ← **Disable key expiry**، حتى لا ينقطع بعد عدة أشهر.

> Tailscale تعمل كخدمة في Windows، أي أنها تبدأ تلقائياً مع تشغيل الجهاز. راجع خطة الاستخدام المناسبة لعيادة على tailscale.com/pricing.

### 4) سجل A للدومين (في Cloudflare ← DNS ← Records)
| Type | Name | Content | Proxy status |
|---|---|---|---|
| A | `@` (أي eplus.life) | عنوان Tailscale للسيرفر، مثلاً `100.101.102.103` | **DNS only** (الغيمة رمادية) ⚠️ |

- العنوان `100.x.x.x` عنوان خاص، فلا يمكن لأي جهاز على الإنترنت الوصول إليه إلا عبر Tailscale.
- ⚠️ لا تفعّل الغيمة البرتقالية (Proxied). إذا فُعّلت فلن يعمل الدومين، ولن تمر البيانات عبر Cloudflare.

### 5) على جهاز السيرفر: تحديث البرنامج وتفعيل الدومين
1. شغّل `update.bat` لجلب هذه النسخة. يأخذ التحديث نسخة احتياطية أولاً.
2. انقر بالزر الأيمن على **`domain-setup.bat`** ← **Run as administrator**، ثم أدخل:
   - الدومين: `eplus.life`
   - إيميل لتنبيهات الشهادة
   - Cloudflare API Token

السكربت ينفّذ ما يلي:
- يأخذ نسخة احتياطية؛
- يحفظ نسخة من الإعدادات في `.env.before-domain`؛
- يضيف قاعدة Firewall تسمح بالمنفذ 443 من شبكة العيادة ومن Tailscale فقط؛
- يشغّل Caddy وينتظر حتى تصدر الشهادة.

إذا نجح تظهر الرسالة: `HTTPS is working on this computer`.

### 6) أجهزة العيادة
اختر إحدى الطرق لكل جهاز:
- **بدون أي تغيير:** يستمر الجهاز بالدخول عبر `http://192.168.1.93:4080` كما هو الآن.
- **كمبيوتر داخل العيادة يريد الدومين:** شغّل `domain-hosts.bat` عليه كمسؤول (Run as administrator) وأدخل عنوان السيرفر المحلي. بعدها يفتح `https://eplus.life` مباشرة عبر شبكة العيادة.
- **تابلت أو هاتف:** ثبّت تطبيق Tailscale وسجّل الدخول، فيعمل `https://eplus.life` داخل العيادة وخارجها.

### 7) الوصول من خارج العيادة
1. على اللابتوب أو الهاتف: ثبّت Tailscale وسجّل الدخول بنفس الحساب، أو بحساب دعوته من لوحة Tailscale ← **Users ← Invite**.
2. افتح `https://eplus.life`.

**شرط أساسي:** يعمل هذا فقط ما دام **جهاز السيرفر في العيادة شغالاً ومتصلاً بالإنترنت.**

## التشغيل المستقر

| المطلوب | كيف |
|---|---|
| تشغيل البرنامج تلقائياً | Docker Desktop ← Settings ← General ← ✅ **Start Docker Desktop when you sign in**. الخدمات مضبوطة على `restart: unless-stopped`، فتعود تلقائياً بعد إعادة التشغيل أو أي توقف. |
| تسجيل دخول Windows تلقائياً | Docker Desktop يحتاج تسجيل دخول المستخدم: شغّل `netplwiz` ← ألغِ «Users must enter a user name and password» ← اكتب كلمة المرور. أو استخدم أداة Autologon من Microsoft Sysinternals. |
| عدم دخول الجهاز في السكون | Settings ← System ← Power ← Sleep: **Never**. |
| عودة الجهاز بعد انقطاع الكهرباء | من إعدادات BIOS فعّل: Restore on AC Power Loss = **Power On**. ويُفضّل جهاز UPS. |
| Tailscale | خدمة Windows تعمل تلقائياً. |
| السجلات | `docker compose logs app` و`docker compose logs caddy`. السجلات محدودة الحجم تلقائياً. |
| مراقبة القاعدة | فحص صحة كل 30 ثانية يتصل بقاعدة البيانات، و**`check-system.bat`** يعرض الحالة كاملة. |
| النسخ الاحتياطية | يومياً تلقائياً في مجلد `backups`، كما هو الآن. انسخها أسبوعياً لقرص خارجي. |

## الأمان

- **HTTPS عبر الدومين:**
  - شهادة رسمية؛
  - HSTS للدومين فقط؛
  - كوكيز الجلسة `Secure + HttpOnly + SameSite=Strict`.
- **الدخول بالـ IP (HTTP):**
  - الكوكيز `HttpOnly + SameSite=Strict` بدون Secure، وإلا لما عمل تسجيل الدخول.
  - ⚠️ HTTP غير مشفّر، فلا يُعتبر آمناً على شبكة Wi-Fi غير موثوقة. اجعل شبكة الموظفين منفصلة عن **شبكة الضيوف (Guest Wi-Fi)**.
  - على الأجهزة الحساسة استخدم `https://eplus.life` بدل العنوان.
- **قاعدة البيانات:** لا تُنشر على أي منفذ خارج Docker. يمكنك التحقق في البند [4] من `check-system.bat`.
- **رؤوس الطلبات:** البرنامج يثق برؤوس `X-Forwarded-*` من Caddy فقط، أي من عنوانه الثابت داخل Docker. لا يستطيع جهاز آخر انتحالها، وهذا مختبر.
- **الملفات الحساسة:** ملف `.env` والإعدادات غير موجودة داخل صورة البرنامج أصلاً، ولا يقدّم الخادم إلا البرنامج نفسه.
- **الصلاحيات ونظام تسجيل الدخول:** بقيت كما هي دون تغيير.
- **كلمات المرور ومفاتيح الاتصال:** لم يتغير أي منها. أُضيف فقط `DNS_API_TOKEN` إلى `.env`. احفظ هذا الملف ولا تشاركه.

## التراجع
- **`domain-disable.bat`**: يوقف الدومين فقط. يبقى الدخول بالـ IP، ولا تُلمس أي بيانات.
- الإعدادات السابقة محفوظة في `.env.before-domain`.

## مشاكل شائعة
- **الشهادة لا تصدر:**
  - تأكد أن الدومين **Active** في Cloudflare؛
  - وأن الـ Token من نوع Edit zone DNS لنفس الدومين.
  - راجع `docker compose logs caddy`.
- **الدومين لا يفتح داخل العيادة:** بعض الراوترات تمنع ربط اسم دومين عام بعنوان خاص (DNS rebinding protection). استخدم `domain-hosts.bat` أو Tailscale على ذلك الجهاز.
- **المنفذ 443 مستخدم على السيرفر:** أوقف البرنامج الذي يستخدمه، مثل IIS أو Skype القديم.
